# 提醒、草稿与 OCR 评测优化（2026-10-17）

后续 OCR 改进与对照见 [2026-10-18 单元格优化记录](OCR_CELL_OPTIMIZATION.md)。本文保留首次基线。

## 提醒

- 去重记录从最后一个 `@` 拆分，兼容已有的 `时段ID@上课日期@触发日期` 记录；保留最近七天记录，丢弃无效日期。
- 日常重排仅取消持久化的闹钟编号。所有课表扫描、旧编号公式清理只执行一次；清理成功后才写迁移标记。
- 先持久化完整编号集合，再逐个注册闹钟。中途失败或进程退出后，下次重排仍能取消部分注册的闹钟。
- 取消时使用 `FLAG_NO_CREATE`，不为不存在的历史闹钟创建 PendingIntent。
- 开启提醒但未来一周无课时仍安排每日维护；关闭提醒时取消维护。
- 排程失败在日志记录异常类型，设置页显示重新开启提醒的操作提示；不保存异常正文或课程信息。取消信号继续传播。

## 粘贴草稿

- 草稿保存在应用的 `noBackupFilesDir/paste-import-draft.txt`，不进入 Activity 状态 Bundle 或系统备份。
- 后台串行写入，合并尚未开始的快速输入；先写临时文件并同步，再原子替换。页面退出不会取消已提交的保存。
- 页面打开时异步恢复，恢复完成前禁止编辑，以免旧草稿覆盖新输入。清空操作也会落盘。
- 读取或写入失败会显示提示。保存是异步的，进程在最新一次写入完成前被强制终止时，仍可能恢复到上一次完成保存的内容。

## OCR 基线

已有真实截图 `app/src/androidTest/assets/selection-details.jpg`，对应答案增加独立的十二个时段记录，包括散周 `[4,9,10,14,15,16]`。

`OcrBenchmarkTest.compareStructuredScreenshotVariantsWithGroundTruth` 输出：

- `exactScheduleRecall` / `exactSchedulePrecision`：名称、星期、起始节次、节数与实际周次全部匹配；按多重集合匹配，重复候选不能增加正确数。
- `wholeTableCorrect`：上述全部时段精确匹配且无额外候选。此指标不包含教师和地点，不能称为所有字段的整格正确率。
- `missingSessions` / `incorrectSessions`：漏掉的标准时段和错误或额外候选。
- `reviewInterception`：错误候选中带 `needsReview` 标记的比例，无错误候选时为 null；漏掉的课程单独报告。
- 耗时、采样 PSS、字段无效数和警告继续输出。

原图为真实样本；低对比度、旋转和三段拼接属于同一截图的合成变体，不计作新增真实样本。报告从 instrumentation/logcat 流式读取，不生成设备测试文件。

仍需补充真实拍照、扫描 PDF 和不同来源的长截图与人工答案，才能对这些场景作准确率结论。本轮不修改 OCR 模型，不能据此宣称识别率提升。

Android 14 模拟器执行完整识别流程，单次运行约 297 秒。标准答案为十二个不同上课时段；三段拼接重复同一课表，仍以十二个不重复时段为目标。

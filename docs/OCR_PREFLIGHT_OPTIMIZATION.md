# OCR 重复画面预检与课程名确认（2026-10-18）

接续 [上一轮单元格优化](OCR_CELL_OPTIMIZATION.md)，沿用同一截图、标准答案和合成方式。

## 变化

- 对足够高的图片先检查完整画面是否逐像素重复，在一份画面中确认课程名称及时间表头后才采用优化路径。避免先对整张重复长图运行 OCR，再重新识别一份裁剪。
- `parseImage` 和实际导入入口均使用预检；一份画面的初始文字只识别一次并复用，实际导入不再额外扫描重复部分的横线、色块与网格。OCR 结果仍标记为 OCR 路径。
- 文字和区域坐标映射回原长图，校对继续使用原图。任何像素不同、没有明细表表头或比例不适合时回退既有流程。
- 完整课程名候选可直接从记录卡片确认，无须原图文件或重新解析整行。对话框显示原名与候选，确认前不改变记录。
- 只更新名称及名称的已校对标记；教师、教室、星期、节次、散周、来源和其他已校对标记继续保留。后续重新识别也保护已确认的名称。只有在编辑器关闭时才可从卡片操作，避免丢弃尚未保存的输入。
- 字典外原文保护继续保留。检查现有模型元数据确认原识别中的“勢”和“カ”不在字典内，这些案例仍由用户明确确认候选。

留白和降低短尾行门槛的实验没有提高固定样本的主匹配率，还观察到高分读数丢失括号，因此没有将这些调整纳入产品。诊断测试保留以便复现。本轮没有更换模型，没有引入样本答案、云端识别或训练。

## 验证约束

重复画面测试检查十二个时段、原长图坐标、每条候选对应的区域，以及单像素差异导致回退。名称测试检查确认前和取消时不改变记录、确认时不影响其他值及校对标记，以及后续重新识别继续保护已确认字段。

设备测试只在 Android 14 模拟器运行。一个真实截图及其合成变体不能代表拍照、扫描 PDF 或其他学校课表；仍需校对。

本地日志位于忽略目录 `.artifacts/ocr-followup-20261018/`。本轮没有创建 ADB 截图、录屏或 UI XML 文件，测试输出直接流向电脑。

## 继续优化：同源时段的批量名称确认

名称确认对话框增加可选的“同时应用到 N 条记录”。默认的“采用候选课程名”仍只修改当前记录。

批量关联要求明确的非空来源区域或非空课程分组，同时当前名称、教师、目标课程和候选名称一致。其他已人工修改过名称或已完成校对的记录、另建独立课程、不同教师或目标、没有相同候选的记录不会进入批量范围。完成校对但没有改字的名称也受保护。同名本身不能建立关联。不同地点、星期、节次和周次属于同一课程的不同上课时段，确认时各自保留。

提交只修改预览中的记录。按编号建立索引并核对记录快照，拒绝过期或重复编号；对话框发现当前记录变化时禁用提交并提示重新选择。名称提示与其他字段共用同一原因文字时，也会保留其他字段的提示。

校对页的重复及冲突分析按候选、已有课程、设置和导入模式缓存。打开或关闭名称确认等不改变输入的操作可复用分析结果，输入变化后重新计算。

本节验证针对校对流程、字段保护及分析结果复用；识别率和 OCR 耗时仍引用上方的对应基准。

- 最终 155 项 JVM 单元测试通过，0 failures / errors。验证了关联边界、空来源、已完成校对或已修改名称的排除、不同教室和散周保留、过期快照、重复编号及共享提示保留。
- 最终 4 项 Android 14 模拟器界面回归通过：显式批量确认、默认仅改一条、取消不修改、记录变化后禁用提交。批量用例包含同源时段、人工修改名称、已完成校对和不同来源的记录，仅前两条待校对同源时段被修改。
- Lint：0 errors、41 warnings、4 hints。缓存优化没有进行独立耗时测量。

# 输入框焦点与键盘闪动复盘

日期：2026-10-02。涉及课程编辑页；最终验证包为 `1.7.1-preview`、`versionCode 163`（b163）。

## 用户看到的问题

最初，键盘打开时点击另一个输入框，光标先移动过去，随后焦点和键盘一起关闭。后续移除全局清焦点后，用户又发现切换输入框时键盘会先收起再弹出；普通点击每次出现，长按等待光标移动过去则不出现。

这两种症状不能混为一谈：一项是应用额外清除了焦点，另一项涉及框架在输入会话交接时发送了隐藏、显示请求。不能笼统解释为“系统行为”或“某个输入法正常重启”。

## 最终约定的交互

| 操作 | 应有行为 |
| --- | --- |
| 点击当前或另一个输入框，包括标签和装饰区域 | 保持或转移编辑焦点，键盘保持打开 |
| 点击空白处、课程预览 | 结束输入，清除焦点、光标和选中手柄，收起键盘 |
| 点击星期、节次、颜色、保存等非输入控件 | 结束输入，同时执行控件原有操作 |
| 先手动收起键盘，再点击空白处或非输入控件 | 清除残留焦点和光标 |
| 滚动、拖动、长按 | 不当作结束输入的点击 |

不新增页面按钮，不依靠键盘隐藏事件推断用户是否完成编辑。单独手动收起键盘允许保留焦点；之后的外部点击负责结束编辑。

## 处理过程与教训

1. **原来的全局联动不合适。** `ClearFocusOnImeDismiss` 在检测到 IME 从可见变为不可见时立即调用 `clearFocus()`，会放大输入会话切换期间的隐藏问题。
2. **b160 的 300 毫秒延迟只是补丁。** 它等待键盘重新出现以取消清焦点，但无法准确区分主动收起和临时隐藏。不能把固定等待描述成可靠的“确认”。此逻辑最终删除。
3. **b161 交回系统后，焦点保留属于预期。** 键盘关闭和输入框失焦是独立状态。仅删除联动不能满足用户对结束编辑的完整需求。
4. **b162 增加明确的外部点击结束输入。** `EndInputOnOutsideTap` 观察点击但不消费事件，输入框标记自己的触摸，非输入控件仍执行原来的动作；排除超出触摸阈值的移动、长按和多指操作。
5. **键盘仍闪动，需要查框架。** 实际应用的 `ImeTracker` 日志出现紧邻的 `onRequestHide`、`onRequestShow`。输入框边界判断、空点击容器、新旧输入 API、提前请求焦点都曾被怀疑或尝试；这些尝试没有形成最终修复，已经撤回。不能把一个尚未验证的猜测提前宣布为根因。
6. **b163 使用官方修复版本。** 将 Compose BOM 从 `2026.08.00` 升到 `2026.09.00`，对应 Compose UI / Foundation / Runtime 1.12.1。没有保留 300 毫秒等待、启动时的实验性框架开关、输入控件迁移或强制提前抢焦点。

## 上游问题与最终修复

本次使用的 Compose UI 1.12.0 存在文本输入事件调度回归。焦点从 A 交给 B 时，旧会话停止和新会话启动可能分开发送隐藏、显示键盘请求。

官方修复记录关闭 `isOutOfFrameSchedulerForTextInputEventsEnabled`，恢复按帧合并输入命令的路径，并注明该变更用于 Compose 1.12.1 稳定版，关联问题 `530704636`：

- [官方修复提交](https://android.googlesource.com/platform/frameworks/support/+/9d039d835daa553abea4ff30ccf569219a6c2fc6)
- [Compose UI 1.12.1 发布说明](https://developer.android.com/jetpack/androidx/releases/compose-ui#1.12.1)
- [BOM 2026.09.00 官方依赖清单](https://dl.google.com/dl/android/maven2/androidx/compose/compose-bom/2026.09.00/compose-bom-2026.09.00.pom)

升级修复版比在应用内长期复制实验性开关更容易维护。本次最终改动是依赖版本升级；现有外部点击结束输入的产品规则保持不变。

## 测试中踩到的坑

**“切换之后能输入”不等于“切换过程没有闪动”。** 早期测试只检查最终焦点、键盘状态和输入结果，漏掉了中间关闭、再打开的过程。以后应在首次键盘展开稳定后开始记录可见 → 不可见的次数。

**原生事件也不能直接混用模拟渲染时钟。** 在 `createComposeRule()` 的模拟时钟下直接注入原生触摸，会改变重新组合和输入会话启动的时机。本次这种混合测试即使升级后仍报告闪动，因此不能单独据此判断生产环境是否修好，也不能通过放宽断言掩盖失败。

保留两种互补的测试：

- `EndInputOnOutsideTapTest`：Compose 测试环境，验证空白处、非输入控件、手动隐藏后清焦点、标签点击、滚动、长按，以及切换后的输入行为。
- `NativeKeyboardSwitchTest`：使用 `ActivityScenarioRule` 和真实渲染时钟；通过 `UiAutomation` 注入 `SOURCE_TOUCHSCREEN`、`TOOL_TYPE_FINGER` 的 DOWN / UP，实际切换课程编辑弹窗的教师、地点输入框，记录键盘关闭次数。

原生测试通过无障碍树查找输入框位置：启用 `FLAG_REPORT_VIEW_IDS`，并遍历节点匹配导出的测试标签。避免硬编码屏幕坐标，也不要把节点查找超时误当成键盘行为失败。

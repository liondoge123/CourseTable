# 导入优化（2026-10-15）

基于 `coursetable-import-optimization-plan.md`，接续工作区已有的多时段课程、分散周次、OCR 分歧和长图处理。本轮不更换识别模型，不增加云端上传或 API Key。

## 用户入口

- 导入页新增「粘贴导入」：教务页面复制出来的制表符表格、CSV、AI 课程 JSON、单课表分享文本均进入现有 `UnifiedImportReview`。缺失时间保留为待修正项，不自动补成整学期。
- 粘贴页可主动读取剪贴板、清空内容和复制 AI 识别提示词。提示词按当前课表的总周数和节次时间生成，用户自行选择 AI 并发送图片。解析失败保留文本，退出校对回到原粘贴草稿。
- 设置 → 数据与安全 →「复制当前课表分享文本」。仅包含当前课表的课程与上课时段，不包含其他课表、数据库 ID、登录凭据或全局设置。接收者粘贴后选择目标课表并校对；学期开始日和节次方案沿用接收者的课表。
- 图片识别失败和教务导入页均提供粘贴入口。

支持的教务文本保留单元格之间的 Tab、行之间的换行。例如：

```text
授课教师\t教室\t课程名\t教学时间
张三\tA301\t高等数学\t1-16周 星期一 1-2节
```

上例的 `\t` 表示真实制表符。失去列结构的纯文本、HTML rowspan/colspan 尚不解析，可使用同一入口的 AI 提示词转换。

## 课程 JSON 与分享协议

```json
{
  "courses": [
    {
      "name": "专业应用创新实践Ⅱ",
      "teacher": "张三",
      "location": "X1412[犀浦]",
      "dayOfWeek": 3,
      "startSection": 11,
      "duration": 2,
      "weeks": [4, 9, 10, 14, 15, 16]
    }
  ]
}
```

也接受顶层课程数组、完整的 JSON Markdown 代码块、`startWeek`/`endWeek`/`weekType` 和 `selectedWeeksCsv`。`weeks` 表示实际选中的周次；未知周次请省略它并填写 `startWeek: 0, endWeek: 0`。未知星期、节次、节数填 0，未知文字填空字符串。不同星期/节次/地点用不同记录。

分享文本以 `CourseTable课表分享 v1` 加换行开头，后接 `format: "coursetable-share"`、`version: 1`、`title` 和 `courses`。可选的 `group` 只在一次导入内关联同一课程的多个时段，不作为数据库 ID 使用。不支持的协议版本会明确拒绝；整库备份仍走备份恢复入口。

限额：512,000 字符、2,000 条课程、文字字段 256 字、JSON 嵌套 32 层、文本 10,000 行/128 列；超限显示可操作错误，不静默截断。

## 图片和 PDF

- Tiny 复核使用模型实际字符字典。ML Kit 原文含字典外字符时禁止覆盖；自由文本保持原文并保留分歧。只有两侧都属于时间语法、原文不合法而复核结果合法时，才允许结构字段替换，并保留校对提示。
- 明细表头使用完整单元格同义词。较长表头允许一个字符的编辑距离，短表头仅精确匹配；支持列顺序变化、缺少班号、教师和地点单列，跨页表头和定点补识别使用同一套匹配规则。
- 显式记录标签格式、明细、周表、坐标路线的尝试。根据字段合法率、存疑比例和已解析周次文本的覆盖率计算启发式分数；低于 0.85 时换路线。新路线须提高分数并保住已识别的合法时段数。分数不是经实测校准的概率。
- 多记录共享一个视觉色块但未提供明确节次时，标记跨度存疑并触发坐标重试。
- 一次 meeting 中的散周归为一个候选，使用既有周次表示，保留空档及单双周，不生成多条候选让用户拼接。
- 历史词库仅来自当前目标课表。课程名称长于等于四字、唯一且仅有一个汉字替换时可修正并标记；数字、罗马数字、字母差异和歧义不自动修正。教师只提供相近历史姓名供确认。地点模式异常只标记，不阻止保存或自动改写。

## 验证边界

JVM 覆盖 JSON/Tab/CSV、分享往返、恶意与超限输入、表头变体、错误路由重试、色块误跨度、散周、历史纠错歧义、OCR 采纳规则、教务失败分型与学期推导。Android 流程覆盖粘贴进入统一校对、返回保留草稿、错误文本修正后重试。

2026-10-15 本轮验证：134 项 JVM 测试通过；Android 14 的 Medium_Phone 模拟器上，`PasteImportTest` 2 项、`EndInputOnOutsideTapTest` 9 项、`NativeKeyboardSwitchTest` 1 项通过。原生测试使用真实渲染时钟与原生手指事件，连续切换 6 次未检测到键盘关闭。首次键盘测试期间模拟器断开，重启后首次原生测试输入框定位超时，后续复跑通过；未据此修改既有焦点实现。原始记录保存在忽略目录 `.artifacts/import-optimization-20261015/`，ADB 临时会话目录已清理。模拟器结果不能替代手机及实际输入法验证。Lint 为 0 errors、53 warnings、4 hints。

已有截图转写和 PDF token 回归属于结构解析测试，**不代表实际图片 OCR 准确率**。当前仓库和所提供文件中没有路线文档提到的 `eval-sample-01.jpg` / `ground-truth.json`，不能据此宣称识别率提高了某个百分比。真实样张仍需补齐后，以整格正确率、整表全对率、存疑拦截率做前后对照。

本轮没有实现：四边形透视校正、扫码/二维码分享、App 直连 VLM、第二教务厂商、HTML 粘贴结构解析。已有倾斜校正、长图 OCR 分块沿用；真实拍照、扫描 PDF 和长截图效果仍需真实样张与手机验证。

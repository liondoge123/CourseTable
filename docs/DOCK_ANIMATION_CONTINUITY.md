# Dock 镜片连续性与切页停顿（2026-10-25）

## 弹层与二级页返回时序

Dock 显示由弹层和二级页的视觉遮挡请求统一控制，不再依赖页面卸载。普通小对话框及菜单不隐藏 Dock；课程详情、编辑弹层和二级页隐藏 Dock。点击返回时从退出开始恢复，预测返回在手势确认提交（COMMITTING）时恢复，和页面退场并行播放 140ms 动画。跟手预览、取消和拒绝返回期间仍保持隐藏；页面仍保留原来的挂载和交互拦截，退出未结束时不响应 Dock 导航或添加操作。

独立的导入确认页同样登记遮挡请求；多个页面或弹层叠加时，必须释放全部遮挡请求后才恢复 Dock。`PredictiveBackContinuityTest` 新增弹层手势取消/提交、二级页按钮/手势返回的时序断言。此轮完成编译和 lint，未连接设备，新增 instrumentation 测试尚未实测。

后续修正：抽屉的手势阶段原先仅在 `SideEffect` 中读取，没有订阅 COMMITTING 状态变化，实际仍等到 COMPLETED 才恢复 Dock。现改为组合阶段读取状态，再将值提交给遮挡控制器。只读 Medium_Phone 模拟器通过四项设备测试：抽屉手势取消/提交、二级页按钮返回、二级页手势返回，以及 `NativePredictiveBackTest.nativeSheetBackRevealsDockBeforeTheSheetIsRemoved`。后者用原生手指边缘事件和 Choreographer 确认抽屉仍挂载时已释放 Dock 遮挡；日志在 `.artifacts/dock-back-20261025/verified-tests.log`。这不替代用户手机的视觉与手感复核。

## 确认的状态交接问题

完整的原生触摸采样发现：按下 Dock 后，镜片已经向目标标签移动；松手提交页面选择时，父组合可能尚未把新的 `selectedIndex` 传回 Dock。此时 `dragging` 已变为 false，原来的 `LaunchedEffect(selectedIndex, dragging)` 会把仍然有效的旧选中项解释成新的动画目标，将镜片拉回源标签。父组合随后传入新选中项，又触发一次向前动画。

一条课程 → 导入的诊断记录中，按下后约 20 ms 发起镜片移动，约 87 ms 松手并提交页面；随后镜片目标被改回 1，在约 188 ms 再改为 2。该轨迹来自 `.artifacts/nav-fix-20261025/motion-only-a.log`，可以解释镜片移动过程中的停顿或回拉，不能解释所有显示长帧。

修正使用待确认选择 `(source, target)`：松手后维持已经提交的镜片目标，父组件仍返回 source 时不重定向；收到 target 或其他明确的新选中项后解除待确认状态并同步。新的按压和取消会结束旧的待确认请求。此交接不依赖延时，也不把镜片位置绑定到页面动画分数。

## 实现

- 将物理按压与选择提交拆开。`commitToValue` 延续当前镜片弹簧，同目标不重复启动；语义点击和外部选中项变化仍通过 `animateToValue` 产生完整按压反馈。保留旧释放任务不能收缩新按压的保护。
- 标签缩放改为延迟读取提供器，缩放和面板偏移在 `graphicsLayer` 读取。镜片缩放帧与拖动帧复用标签内容的组合。
- 加号容器采用固定测量尺寸，在图层和放置阶段保持原来的整体居中轨迹；形状在绘制阶段读取进度，仅在显示、连接、分离等边界改变组合结构。狭窄约束仍采用原来的宽度截断，RTL 使用与形状一致的物理坐标定位加号。
- 页面弹簧、镜片弹簧、实时页面采样、模糊、折射、色散、高光和阴影参数保留。没有添加整页预载或冻结背景。

## 诊断与回归

`RootNavigationFrameProfileTest` 使用原生手指事件和真实渲染时钟，从 ACTION_DOWN 记录到页面、镜片和加号全部落定。输出松手、页面请求、镜片释放的时间戳，保留各帧耗时及运动值，区分首次进入与已访问页面。组统计只连接同一轮的连续帧，长间隔不再因超过 300 ms 被丢弃。原始轮次分段输出，避免超过 Binder 单次事务大小。

落定判断还要求应用确认收到抬手事件，并在页面请求后报告新的页面状态，避免输入尚在排队时把旧的静止状态算作完成。坐标查询先清除 UiAutomation 缓存，点击完整标签控件的中心；可访问性坐标按当前原生窗口尺寸转换，记录转换比例和原生窗口尺寸。启动时先等待 UI 空闲、窗口焦点和实际绘制的 Dock，原生事件使用同步投递并正确释放压力。页面按课程→导入→设置→导入→课程往返，每次验证目标页，避免测量间额外的重置动画。

一次重置点击未到目标页的旧采样已保留在 `pre-ack/`，不计入最终对照。启动与运行中分辨率覆盖环境下仍出现过未收到触摸的失败，因此最终测量改用启动时原生 540×1200 帧缓冲及 210 dpi，完全不使用 `wm size` / `wm density` 覆盖；旧会话结果不与此环境混合。

显式启用：`-e profileNavigationFrames true`。轮数由 `-e frameProfileRounds 10` 配置；`-e frameProfileMode dock_only` 仅测点击。未启用诊断时不安装逐帧运动观察器。启用 atrace 时，`CourseTable.*` 标记和数值计数器可与 UI 线程、RenderThread 及图形系统轨迹对齐；`UNKNOWN_DELAY` 不直接归因于某个线程。

新增用例覆盖父组件延迟确认、同目标松手的连续轨迹、缩放期间标签组合复用、加号动画期间标签测量复用、RTL 与窄屏居中，以及实际加号点击。现有导航、原生触摸、取消、快速重定向和动画倍率用例一起执行。

最终构建的 202 项 JVM 测试和 `lintDebug` 通过。独立模拟器最终通过 56 项 Android 回归：镜片与布局 12 项，其余为根导航、原生触摸及动画倍率用例。在原生分辨率的新会话中，56 项再次全部通过，日志为 `native-regressions.log`；编译及 JVM / lint 日志为 `final-validation-build.log`。

## 最终对照结果

最终以会话开始时的工作区（含已有未提交修改）加相同诊断钩子作为基线，使用相同 Debug 构建类型和数据。两段采样各五轮，基线、三项单变量与组合版本交替安装：基线和组合各 80 轮（点击/滑动各四方向、每方向十轮），单变量各 40 轮点击，共 **280 轮**。全部通过，FrameMetrics 回调丢失数为 0；没有建立大型课程负载。

| 点击方向 | 基线间隔 P95 | 组合间隔 P95 | 基线 >25 ms 间隔占比 | 组合 >25 ms 间隔占比 |
| --- | ---: | ---: | ---: | ---: |
| 课程 → 导入 | 66.7 ms | 50.0 ms | 41.6% | 22.7% |
| 导入 → 设置 | 66.7 ms | 50.0 ms | 45.3% | 20.9% |
| 设置 → 导入 | 66.7 ms | 50.0 ms | 46.8% | 15.5% |
| 导入 → 课程 | 66.7 ms | 33.3 ms | 45.0% | 23.0% |

四条滑动路径的间隔 P95 均由 50.0 ms 降到 33.3 ms，>25 ms 间隔占比由约 41%–44% 降到约 18%–24%。只统计已访问页面时，点击 P95 仍从基线 66.7 ms 降到组合的 33.3–50.0 ms；首次进入与已访问分类保存在原始轮次和汇总 JSON 中。

图层读取单变量的 >25 ms 间隔占比为约 16%–23%，是本次帧节奏改善的主要证据；仅修改镜片交接或加号布局没有达到相同幅度。各项收益不能相加。40 次组合版本点击均只有一次 `lens.press`，基线 40 次均为两次；这与轨迹连续性回归相互补充。最终样本未捕获镜片目标回退，较早的高负载记录和延迟确认回归用于验证该竞态。

这些是绘制帧时间戳间隔，不是面板刷新率或物理手机 FPS。原始逐帧/运动记录为 `clean-*.log`，汇总为 `comparison-summary.json`；每轮保留实际按下/抬手时间和窗口坐标映射。

## 系统轨迹与降速对照

另外采集基线、组合与组合 2× 系统动画倍率各一轮点击/滑动对照，三项诊断全部通过。`CourseTable.*` 标记将输入、页面请求和镜片释放与 UI 线程及 RenderThread 对齐，汇总只纳入按下至落定窗口，排除启动与测试框架的长跨度。

该单次轨迹中，主线程 `AndroidOwner:measureAndLayout` 的 P95 从约 9.35 ms 降到 6.26 ms，RenderThread `flush layers` 从约 24.24 ms 降到 14.23 ms；RenderThread `DrawFrames` 的 P95 仍约 35 ms，`FrameMetrics.GPU_DURATION` 的 P95 约 10.8 ms。轨迹跨度可能包含等待，嵌套区段也不能相加；这些单轮结果用于定位残余开销，不取代 280 轮对照，也不能直接归因于物理手机的 GPU 或驱动。

2× 倍率将完整落定窗口的点击中位数从约 1.06 s 拉长到约 1.81 s（含镜片/加号收尾与静止确认），仍存在长帧间隔。产品未调整时长或弹簧参数。轨迹与汇总分别为 `*.atrace`、`trace-*.log` 和 `trace-summary.json`；诊断结束已恢复原系统动画设置。

## 环境与未完成的设备确认

第一轮 1536 MB / 2 核模拟器数据仅用于发现状态交接轨迹。部分采样与编译并行，随后模拟器又出现 Activity 生命周期销毁超时及系统 watchdog 堆栈采集；这些结果不用于计算优化收益。最终对照使用冷启动的独立只读模拟器，Android 14 / API 34、60 Hz、2048 MB / 4 核、原生 540×1200 / 210 dpi，NVIDIA host OpenGL、Vulkan 关闭；统一配置且不与编译并行。

冷启动后的第一次完整回归在第 53 项被后台 WebView 更新打断。`clean-regression-crash.log` 明确记录了系统安装 WebView 时主动终止 CourseTable 进程；在只读会话内关闭网络及应用商店后，重新执行的 56 项全部通过。旧的被中断运行不计作成功回归。

所有诊断输出保存在忽略目录 `.artifacts/nav-fix-20261025/`。图像和系统轨迹直接流到电脑，未在设备上创建截图、录屏或 UI XML 文件，没有待清理的设备测试文件。本次只读模拟器已退出，最后的 `testDebugUnitTest` / `lintDebug` 检查通过，日志为 `final-checks.log`。模拟器数据描述相对对照，不代表物理手机帧率；完整修复的观感仍需在出现问题的手机上确认。

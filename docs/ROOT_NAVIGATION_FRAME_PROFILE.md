# Dock 点击与滑动停顿排查（2026-10-23，b235/b236）

本文记录当时 Pager 方案的对照结果。b238 曾恢复独立 Dock 短距离位移加淡入淡出；b239 将点击与手势统一为整屏左右平移；b240 将固定 180 ms 收尾改为继承释放速度的平滑弹簧吸附。当前实现见 [ROOT_NAVIGATION.md](ROOT_NAVIGATION.md)。下面的旧方案数据不能当作新方案的帧率测量。

## 结论

点击路径能复现比手势滑动更大的绘制帧时间戳间隔；源码没有为 Dock 点击设置独立的低帧率上限。逐帧推进分页的逻辑检查也没有发现动画数值在中途停更。

确认了一项额外负担：b235 点击时将 `beyondViewportPageCount` 从 0 改为 1。在课程/导入之间移动时，这会额外准备离屏的课表等页面，与实际参与切换的页面和原镜片动画争用渲染时间。只关闭这项预载、保持其余代码和镜片不变，课程相关路径的绘制耗时明显下降，因此最终撤回该预载分支。

另一个确定的历史差异是 `7d40d83` 在加入左右滑动时，也把 Dock 点击从原先约 20% 屏宽的滑动加淡入淡出（进入 220 ms），替换成了整页 Pager 滚动。当前为 260 ms 整页过渡。运动距离增大，会让同样的帧间隔更明显。旧点击实现的诊断也出现了不均匀帧间隔，不能把所有变化概括成“新增功能后点击固定降成某个 FPS”。

## 采样方法

- 实际 `MainActivity`，Android 14 / API 34，60 Hz x86_64 模拟器，ANGLE 软件图形后端，1536 MB 内存；临时显示设置 540×1200 / 210 dpi。
- 不使用 Compose 模拟时钟测帧。通过原生触摸分别点击 Dock 和左右滑动，同一相邻页面双向对照；每种动作每个方向四轮，交替顺序，并在每轮前预热、落定并等待原镜片回弹。
- [FrameMetrics](https://developer.android.com/reference/android/view/FrameMetrics) 记录实际窗口帧的时间戳、绘制、布局、总耗时及回调丢失数。统计点击抬起/滑动开始后相同的 300 ms 窗口；无丢失的指标回调。
- 当前版本 32 轮；滑动功能加入前的 MainActivity 16 轮点击；当前代码仅关闭额外预载 16 轮点击。旧 MainActivity 和关闭预载的对照只存在于诊断 APK，编译后已逐字节恢复工作区源码并校验 SHA-256；最后仅将已验证的预载撤回作为产品修正。

这些是软件渲染模拟器中的相对对照，不能直接换算成用户手机的实际 FPS。帧时间戳间隔也不等同于显示面板的标称刷新率。

## b236 改动与回归

产品改动仅撤回点击期间的额外离屏预载，`beyondViewportPageCount` 固定为 0；镜片、动画曲线/时长和已验证的触摸中断恢复保持原样。191 项 JVM 测试及 40 项 Android 14 模拟器交互回归通过（分页 18、原生手指 4、主导航 10、镜片 6、渲染 2），包括新增“动画中途无逻辑停更”断言。记录为 `.artifacts/nav-frame-fix-build.log`、`.artifacts/nav-frame-fix-regressions.log`，最终预览构建 b236。
